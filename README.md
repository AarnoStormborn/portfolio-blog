# www.hxrsh.tech

Portfolio and blog for Harsh Singh. Hand-written HTML, a purple design system in
`assets/css/style.css`, and blog posts pre-rendered to static pages by a small
Node build. No framework, no bundler, deployed straight from `main` by GitHub
Pages (see `CNAME`).

## Layout

```
index.html      portfolio (hero, about, experience, skills, tech, projects, contact)
blog.html       post list, rendered client-side from posts.json
post.html       fallback renderer for ?post=<slug>; used for drafts and previews
404.html        GENERATED by the build
feed.xml        GENERATED  RSS 2.0
atom.xml        GENERATED  Atom
sitemap.xml     GENERATED  URL list for crawlers
robots.txt      GENERATED  allow-all + sitemap pointer
posts.json      GENERATED  manifest: authored fields + derived staticUrl/readingTime
blogs/<slug>/   one source blog.md + its images; index.html is GENERATED
assets/         css/ js/ fonts/ data/ images/
scripts/        build + validation
```

## Publishing a post

1. Add `blogs/<your-slug>/blog.md` and any images next to it.
2. Add an entry to `posts.json`:

   ```json
   {
     "slug": "your-slug",
     "title": "Your Title",
     "date": "2026-09-01",
     "summary": "One or two sentences for the list and og:description.",
     "path": "blogs/your-slug/blog.md"
   }
   ```

   Only `slug` and `path` are strictly required; the build derives the rest from
   front matter or the first lines of the post. Optional: `tags: ["a", "b"]`.
3. Run the build and commit the output:

   ```bash
   npm run build
   git add -A && git commit
   ```

That regenerates `blogs/<slug>/index.html`, `posts.json`, `feed.xml`,
`atom.xml`, `sitemap.xml`, and `404.html`.

### Markdown conventions

- The **first image** in the file becomes the cover and the `og:image`. Use a
  PNG or JPEG — social scrapers (Facebook, WhatsApp, LinkedIn) do not rasterize
  WebP, so the build deliberately points `og:image` at the original, not the
  optimized sibling.
- Image paths are **site-root-relative**, not relative to the `.md` file:
  `blogs/my-post/cover.png`. The build rewrites them to be correct for
  whichever page renders the post.
- A caption is an italic line immediately after an image:

  ```md
  ![alt text](blogs/my-post/diagram.png)
  *the caption*
  ```

- Fenced code blocks are highlighted at build time by highlight.js. Pass a
  language (` ```python `) to get tokens and a corner label.
- Raw HTML is escaped unless the tag is `br`, `kbd`, `sub`, `sup`, `details`,
  `summary`, or `mark` — and those tags have their attributes stripped. This is
  deliberate: markdown gets pasted from elsewhere.

## Commands

| Command | What it does |
| --- | --- |
| `npm run build` | Regenerate every derived file from source. |
| `npm run dev` | Build, then serve the site at `localhost:8000`. |
| `npm run check` | Build in memory and fail if committed output is stale. |
| `npm test` | Renderer unit tests + CSS/JSON/JS syntax checks. |
| `npm run check-links` | Fail on any internal `href`/`src` that does not resolve. |
| `npm run verify` | All of the above; this is what CI runs. |
| `npm run images` | Re-encode images to WebP and rewrite the size manifest. |

## Images

`python3 scripts/optimize-images.py` writes a `.webp` next to each PNG/JPEG and
records intrinsic dimensions in `assets/data/image-dims.json`. The build uses
that manifest to emit `<picture>` plus `width`/`height`, which is what keeps the
blog free of layout shift. WebP is skipped where it is not actually smaller, and
animated GIFs are left alone so they keep animating.

Run it after adding images, and commit `assets/data/image-dims.json` — the
client-side fallback fetches it at runtime.

## Icons

Every technology logo is self-hosted under `assets/images/tech/`, with
`manifest.json` recording where each came from. They were previously hotlinked,
and that broke: BrandFetch started 302-ing free hotlinks to a docs page, which
emptied the whole Generative AI row, LangGraph and HuggingFace in production.
`scripts/fetch-tech-icons.py` re-downloads them, pinned to specific CDN
versions. CI fails if a hotlinked icon CDN reappears in any HTML file.

## Analytics

GoatCounter, cookieless, configured in `scripts/site.config.js` under
`analytics`. Register the counter code there (currently `hxrsh`) and the snippet
starts reporting; set `enabled: false` to drop it from generated pages.
`skip_local` keeps `localhost` out of the numbers.

## Notes for future edits

- `index.html`, `blog.html` and `post.html` are hand-written and repeat the same
  nav/footer markup. `scripts/templates.js` generates the same partials for
  post pages. Change the nav in **both** places, or the pages drift.
- `assets/js/post-render.js` is shared by the build and the browser, so both
  render paths produce identical HTML. Keep it a classic script (not ESM) —
  `scripts/build.js` `require()`s it and `post.html` loads it with a tag.
- `scripts/markdown.js` builds an isolated `Marked` instance on purpose.
  `marked.use()` mutates a module-level singleton, which would leak the
  build's HTML policy into anything else that requires marked.
- Theme state is one attribute, `body[data-theme="dark"]`. A tiny inline script
  directly after `<body>` sets it before first paint (an external script would
  flash light first); `assets/js/theme.js` owns everything after that, including
  which toggle icon is visible. The icon is chosen in CSS, not JS, so it is
  correct before scripts run.
- Contrast ratios for the palette are documented inline at the top of
  `assets/css/style.css`. The light-mode text accent is deliberately darker than
  brand purple `#8540f5` so it survives at 14px.
